\section{System overview}
\label{sec:system}

\paragraph{Platform.} Webots R2025a \citep{michel2004} and its model of the
Crazyflie~2.1, a 10\,cm quadrotor \citep{giernacki2017}. Each drone runs its
own Python controller; a supervisor, the \emph{referee}, logs every drone's
true state for the analysis and takes no part in the flight. A quadrotor was
chosen because, unlike a wheeled robot such as the e-puck, it has inertia
and moves in any direction whatever its heading: it is the robot closest to
a boid, and the one real drone flocks use. The Webots model is stronger than
the real drone, so total thrust was capped at about twice the weight, as on
a real Crazyflie, and tilt at 30\textdegree. All drones fly at one altitude;
3D flight is future work.

\paragraph{Maps and worlds.} A map is a small TOML file: the arena, sectors
A and C, walls and pillars. The number of drones~$n$, of leaders~$j$ and a
seed belong to the run: a world generator places the $n$ drones in A at a
fixed density, picks $j$ leaders at random with the seed, and writes the
Webots world. \Cref{fig:maps} shows the three maps used for the experiments.

\paragraph{The controller's layers} are shown in \cref{fig:layers}. Every
drone runs the same controller; a leader differs only by knowing where C is.
\begin{itemize}
  \item \emph{Sensing.} Each drone broadcasts its velocity over infra-red;
        from each packet a receiver gets the sender's velocity, distance and
        direction (errors against ground truth: 1.4\,cm, 0.4\textdegree).
        Position comes from GPS, and obstacles from the map.
  \item \emph{Mission.} The flock forms for 16\,s, then the leaders set off.
        Followers don't know where C is but recognise it once inside, fly
        2.5\,m further in and stop.
  \item \emph{Route} (leaders only): the direction to go, either straight at
        C or along a path the leader plans itself (\cref{sec:planner}).
  \item \emph{Flocking model}: one of three, behind one interface
        (\cref{sec:models}), turning all of the above into a wanted velocity.
  \item \emph{Stopping limit} and \emph{flight}: shared by all models, they
        bound the wanted velocity near walls and neighbours and fly it
        (\cref{sec:flight}), so every model meets the same robot.
\end{itemize}

\paragraph{Tools.} Experiments run without the Webots window, and every
number and figure in \cref{sec:results} is computed by one script from the
runs' logs. The reason behind each choice is recorded in a design log kept
with the code.
